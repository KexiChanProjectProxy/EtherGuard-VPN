# super-multi-control-plane - Work Plan

## TL;DR (For humans)
<!-- Fill this LAST, after the detailed plan below is written, so it summarizes the REAL plan. -->
<!-- Plain English for a non-engineer: NO file paths, NO todo numbers, NO wave/agent/tool names. -->

**What you'll get:** Two or more Super control-plane servers that run side by side, each fully serving edges on its own, and keep each other up to date over one persistent, encrypted, zstd-compressed connection. If a Super dies or becomes unreachable, its edges move to another Super automatically; when it comes back it re-syncs everything. Adding, changing or removing peers on one Super takes effect on all of them.

**Why this approach:** Each edge only ever talks to one Super at a time, so its record has a single writer — that lets Supers merge state with simple "newest version wins" rules (a hybrid logical clock) and a full re-sync whenever a link reconnects, with no consensus protocol and no shared database. The link rides the existing HTTPS endpoint (an HTTP Upgrade, like WebSockets), so the current nginx/TLS setup is reused with one extra location block, and a continuous compression stream keeps the repetitive JSON traffic small.

**What it will NOT do:** No strong consistency or leader election — the cluster is eventually consistent (converges within one report interval after connectivity returns). No relaying of VPN traffic between Supers. No change to how edges sign requests or receive snapshots today; single-Super setups keep working unchanged.

**Effort:** XL
**Risk:** Medium - replication semantics (ordering, tombstones, partition behaviour) and edge failover timing are subtle; mitigated by idempotent versioned apply, in-process multi-Super e2e tests, and a memory budget test.
**Decisions to sanity-check:** remote peers are kept for 10 minutes after the inter-Super link drops (then removed); edges stick to whichever Super they are on and never move back on their own; management changes are replicated and each Super writes its own YAML copy; the first step commits your existing uncommitted device/ changes as a baseline.

### Design specification (normative — every todo references these sections by §)

§A **Identity & versions**
- `SuperID` = `mtypes.Vertex` (uint16), non-special, unique per super, from `SuperConfigV2.Cluster.SelfID`.
- `ClusterVersion{HLC uint64; Origin mtypes.Vertex}`. HLC layout: upper 48 bits = unix wall-clock milliseconds, lower 16 bits = logical counter. Total order: compare HLC, then Origin (larger wins). Zero value = "unversioned" (lowest).
- `hlcClock{last uint64; now func() time.Time; maxSkew time.Duration(1h)}` with `Next() uint64` (wall=now_ms; if wall>lastWall → wall<<16; else last+1; counter overflow → (lastWall+1)<<16) and `Observe(remote uint64)` (last = max(last, min(remote, (now_ms+maxSkew_ms)<<16)); log once/min when clamped). Persisted high-water on restart: `last = max(now, persisted)`.
- Only a DIRECT local mutation mints a new version. Forwarding a remote mutation preserves its version and origin unchanged.

§B **Replicated live record (derived state, NOT input replay)**
```go
type clusterPeerRecord struct {            // wire DTO, cluster-private JSON
  NodeID mtypes.Vertex; NodeName, PubKey string
  Candidates []mtypes.ControlV2Candidate  // already blacklist-filtered by origin
  RelayCostMS *float64
  LatencyMS map[mtypes.Vertex]float64
  Observed []mtypes.ControlV2ObservedEndpoint // this node's votes (observer = NodeID)
  LastSeen time.Time                       // origin wall clock, display only
  Version ClusterVersion; Origin mtypes.Vertex
}
```
- `controlPeerRecord` gains `origin mtypes.Vertex`, `version ClusterVersion`, `receivedAt time.Time` (local clock at last local accept/apply), `observed []ControlV2ObservedEndpoint` (own votes as reported).
- Origin path (unchanged public API): `Register()`, `Report()` stamp `origin=self`, `version=hlc.Next()`, `receivedAt=now()`, and under `s.mu` append an outbox mutation (§C). Heartbeat-only reports (no observable change) still append `peer_alive`.
- Replica apply `applyReplicatedPeerLocked(rec)`: if `rec.Version <= existing.version` → return applied=false (no side effects at all). Else replace view fields, candidates, own votes (`clearObservedVotesForObserverLocked` then set), `LatencyMS` (and `graph.UpdateLatency` for each entry), `origin`, `version`, `receivedAt=now()`; compute `changed` vs previous observable view+hints → `revision++` once and one `peer_change` emit after unlock. Live tombstone check: if `liveTombstones[NodeID] >= rec.Version` → drop.
- `applyReplicatedAliveLocked(NodeID, Version, LastSeen)`: only if record exists with same origin and `Version > existing.version` → update `version`, `receivedAt`, `view.LastSeen`; no revision bump.
- `applyReplicatedDeleteLocked(NodeID, Version)`: if record exists and `Version > existing.version` → delete record + its votes (both as target and observer), set `liveTombstones[NodeID]=Version`, `revision++`, emit `peer_gone`. Always record tombstone if newer than existing tombstone. Live tombstones: in-memory, TTL = 2×PeerAliveTimeout (min 10 min), cap 4096 (evict oldest, log).
- Cross-super conflicts arise only when an edge switches super or a message is replayed; both converge within one ReportInterval because the edge keeps reporting to exactly one super which mints newer versions.

§C **Outbox (ordering) — lock order: ManageV2.mu → ControlState.mu → (outbox is inside ControlState.mu)**
- `type clusterMutation struct{ Seq uint64; Kind string; NodeID mtypes.Vertex; Peer *clusterPeerRecord; Alive *clusterAlive; Registry *clusterRegistryEntry; Params *clusterParams; Version ClusterVersion; Origin mtypes.Vertex; FromLink mtypes.Vertex /*0=local*/ }`.
- `ControlState.outbox []clusterMutation` (cap 4096) + `outboxNotify chan struct{}` (cap 1). Every accepted mutation (local or remote-applied) is appended UNDER `s.mu` with immutable deep-copied payload; drained by the link manager AFTER unlock via `DrainOutbox() ([]clusterMutation, resync bool)`. On overflow: clear outbox, set `resyncNeeded=true`; drain returns resync=true → manager sends `full_sync` to every link. No I/O, no callbacks, no link locks under `s.mu`.
- Remote-applied mutations are appended with `FromLink=<peer SuperID>` so the manager forwards to all OTHER links (N≥3 transit) without echo.

§D **Registry & parameters (management plane)**
- `ControlState.preauthorized map[Vertex]string` → `registry map[Vertex]clusterRegistryEntry{NodeName string; ControlPSKey string; AdditionalCost float64; Version ClusterVersion; Origin Vertex}` + `registryTombstones map[Vertex]ClusterVersion`. `ControlKeyFor` reads registry first when the active record's key differs? NO — rule: registry is authoritative for credentials; `ControlKeyFor` returns `registry[id].ControlPSKey` if present else active record's key (active record key is only a cache set at Register from the registry key). Rotation via `CommitRegistry` updates both registry and, if an active record exists, `record.controlKey` atomically.
- `params` gets `paramsVersion ClusterVersion`.
- New ControlState API: `CommitRegistry(entry, version) (changed bool)`, `RevokeRegistry(nodeID, version) (changed bool)`, `CommitParameters(p, version) (changed bool)` — all version-checked (LWW), all append outbox, `CommitRegistry` bumps revision+emits `peer_change` only if an active record's NodeName changed; `RevokeRegistry` also deletes the active record (→ `peer_gone` + live tombstone). `ExportRegistry()`, `ExportLive()`, `ExportTombstones()` for full_sync.
- Effective NodeName arbitration for duplicate names across NodeIDs (converged deterministic rule, NO mutation): in `snapshotLocked` and in `/manage/super/state`, among entries sharing a NodeName the LOWEST NodeID keeps it; others display `<name>~<NodeID>`. Local `AddPeer` duplicate-name rejection stays.
- ManageV2 (local mutations) become **stage → persist → commit**: build newBase + edge profile, `atomicWriteConfigs`, THEN `state.CommitRegistry/RevokeRegistry/CommitParameters` (cannot fail) and persist `cluster_state.yaml`. No `state.Register` ghost record on AddPeer/UpdatePeer anymore (tests updated: AddPeer emits 0 SSE events; UpdatePeer emits 1 `peer_change` only when an active record's name changed or key rotated). `DeletePeer` → `RevokeRegistry` (registry tombstone + live delete).
- Remote registry apply (`ManageV2.ApplyRemoteRegistry(entry)`, `ApplyRemoteRegistryDelete(id, ver)`, `ApplyRemoteParameters(p, ver)`): under `m.mu`: LWW check against state versions; if newer: update `m.baseConfig.Peers`/parameter fields only (NEVER `NodeName, APIUrl, APIPrefix, ManagementAuth, Cluster`), `atomicWriteConfigs(newBase, nil)` (no edge profile on replicas), then commit to state + `cluster_state.yaml`. If persist fails: do NOT commit, log, set `state.resyncNeeded` (retry via next full_sync).
- Replicated parameter fields (complete list, fix `applyParameters` + `cloneSuperConfigV2` deep copies): `STUNServers, STUNRequestTimeoutSeconds, STUNRefreshIntervalSeconds, PollIntervalSeconds, ReportIntervalSeconds, HeartbeatIntervalSeconds, EventReplay, RelayCostMS, ListenPortPriority, EndpointBlacklist`. `PeerAliveTimeoutSeconds, UsePSKForInterEdge, DampingFilterRadius` remain local (not in ControlV2Parameters).
- `<ConfigDir>/cluster_state.yaml` (atomic write): `{HLCHighWater uint64; ParamsVersion; Registry: {NodeID: {HLC, Origin}}; RegistryTombstones: [{NodeID, HLC, Origin, DeletedAt}]}`. Loaded at startup; YAML `Peers` entries without a recorded version get `ClusterVersion{0, SelfID}`. Registry tombstones TTL 7 days, cap 4096 (drop oldest + log warn). Live state is never persisted.

§E **Link handshake (HTTP/1.1 Upgrade) and crypto**
- Route: `GET {APIPrefix}/cluster/link` served by `ControlHTTPHandler` ONLY when a `clusterAuth` is installed (Cluster configured); otherwise 404.
- Request headers: `Upgrade: eg-cluster/1`, `Connection: Upgrade`, `X-EG-Cluster-ID: <SelfID decimal>`, `X-EG-Timestamp: <unix s>`, `X-EG-Nonce: <hex>`, `X-EG-Cluster-Ephemeral: <base64 32B X25519 pub>`, `X-EG-Cluster-Compression: zstd|none`, `X-EG-Signature: hex(HMAC-SHA256(Secret, canonical))`, canonical = `"eg-cluster/1\nGET\n"+EscapedPath+"\n"+ts+"\n"+nonce+"\n"+clientID+"\n"+base64(clientEph)+"\n"+compression`.
- Server: verify skew ≤60s, nonce cache keyed (clusterID, nonce) (reuse `ControlAuthenticator` machinery via a new `clusterAuthenticator` with the same TTL/caps), clientID ∈ `Cluster.Peers` and ≠ SelfID, signature constant-time. Choose compression = client's if server `Cluster.Compression==zstd` else `none`. Respond `101` with `Upgrade: eg-cluster/1`, `Connection: Upgrade`, `X-EG-Cluster-ID: <serverID>`, `X-EG-Cluster-Ephemeral`, `X-EG-Cluster-Compression`, `X-EG-Signature: hex(HMAC(Secret, "eg-cluster/1-reply\n"+clientNonce+"\n"+serverID+"\n"+base64(serverEph)+"\n"+compression))`; then `http.Hijacker.Hijack()` → keep the returned `*bufio.ReadWriter` (buffered bytes MUST be used). Client verifies reply signature, uses `resp.Body.(io.ReadWriteCloser)`.
- Client transport: dedicated `http.Transport{ForceAttemptHTTP2:false, TLSNextProto: map[string]func(string,*tls.Conn)http.RoundTripper{}, DialContext: 15s}` and `http.Client{Timeout: 0}`; handshake deadline 15s via ctx.
- Keys: `shared = X25519(ownEphPriv, peerEph)`; `salt = SHA256(clientEph||serverEph||clientNonce)`; `prk = HKDF-Extract(sha256, ikm=shared||Secret, salt)`; `key_c2s = HKDF-Expand(prk,"eg-cluster/1 c2s",32)`, `key_s2c = HKDF-Expand(prk,"eg-cluster/1 s2c",32)`. Use `golang.org/x/crypto/curve25519`, `hkdf`, `chacha20poly1305` (all in existing dependency).
- Outer record (each direction, own key & counter): `uint32 BE clen` || `ciphertext`; `ciphertext = AEAD.Seal(nonce=[4 zero bytes || uint64 BE counter], plaintext=stream chunk, AD=the 4-byte length header)`. `clen ≤ 1<<20 + 16`. Counter starts at 0, increments per record; at `1<<62` close the link. Any AEAD failure → close link. Authenticate BEFORE decompress.
- Compression layer (per direction): `zstd.NewWriter(chunkWriter, WithEncoderConcurrency(1), WithWindowSize(256<<10), WithLowerEncoderMem(true), WithEncoderLevel(zstd.SpeedDefault))`; each inner message: write `uint32 BE len || JSON` then `enc.Flush()`; the chunkWriter turns every `Write` (i.e. each Flush's output) into ONE outer record. Reader: `zstd.NewReader(recordReader, WithDecoderConcurrency(1), WithDecoderLowmem(true), WithDecoderMaxWindow(1<<20), WithDecoderMaxMemory(8<<20))` where recordReader yields decrypted plaintext chunks. `none` mode: inner bytes are the plaintext chunk directly. Inner `len ≤ 4<<20`.
- First inner message in each direction MUST be `hello`; anything else → close.

§F **Link protocol messages (JSON, `{"t":"<type>", ...}`)**
`hello{super_id, proto:"eg-cluster/1", hlc}` · `full_sync{part, of, live:[clusterPeerRecord], registry:[clusterRegistryEntry], params:{...,version}, live_tombstones:[{node_id,version}], registry_tombstones:[...]}` (batches of ≤200 live records; receiver merges each batch as a versioned merge — never replace-all; absence ≠ delete) · `peer_upsert{rec}` · `peer_alive{node_id, version, last_seen}` · `peer_delete{node_id, version}` · `registry_upsert{entry}` · `registry_delete{node_id, version}` · `params_update{params, version}` · `ping{hlc}` · `pong{hlc}`. On (re)connect BOTH sides send `hello` then a complete `full_sync`; deltas flow after. Every received `hlc` → `hlcClock.Observe`.

§G **Link manager (`clusterManager`)**
- One `linkPeer` per `Cluster.Peers` entry: dial loop (jittered exponential backoff `ReconnectMinSeconds..ReconnectMaxSeconds`, default 1..30), at most one pending handshake; inbound sessions accepted from the Upgrade handler. Dedupe: if a second established session for the same peer appears, keep the one whose DIALER SuperID is lower, close the other; if only one exists keep it regardless of direction (one-way reachability).
- Heartbeat: `ping` every `HeartbeatSeconds` (10); read deadline `DeadAfterSeconds` (30) refreshed by any record; TCP keepalive on when the conn is `*net.TCPConn`.
- Per-link outbound queue: map keyed by (kind namespace, NodeID) holding the LATEST mutation (coalescing: later version replaces earlier; `peer_alive` is subsumed by a queued `peer_upsert` of the same node), plus FIFO order list; bounds 4096 keys / 16 MiB serialized; overflow → drop queue, mark `needsFullSync`, send `full_sync`.
- Link status exposed to ControlState via `ControlState.SetOriginLinkStatus(origin Vertex, up bool, since time.Time)`; SweepTimeouts rule: records with `origin==self` sweep as today; records with `origin!=self`: never swept while link to origin is up; when down, swept when `now - max(receivedAt, linkDownSince) > RemoteStaleGraceSeconds` (default 600) — local eviction only, NO tombstone, NO outbox. Votes whose observer record is remote-origin follow the same rule; orphan votes (observer record missing) sweep as today.
- Byte counters per link & direction: `inner_bytes` (serialized JSON incl. 4-byte len), `compressed_bytes` (zstd output), `wire_bytes` (outer records incl. header+tag), `messages`; plus `connected_since`, `last_full_sync_at`, `last_rx_at`, `dialer` (bool), `compression`.
- Shutdown: cancel dial loops, close all sessions (hijacked conns), wait for goroutines within ctx deadline. Wired into `superRuntime.Shutdown` step 1.5 (after ticker, before hub.Close).

§H **Edge failover**
- `SuperNodeV2Ref.APIUrls []string` (yaml `APIUrls`); `ResolveAPIUrls()` = normalized (`TrimRight "/"`), deduped, `APIUrl` prepended once if non-empty; Validate requires ≥1 URL, each http(s) with host; all share `APIPrefix`.
- `ControlHTTPClient`: `epoch uint64` and `SwitchBase(url string) (epoch uint64)` (under `c.mu`: BaseURL=url, current=nil, lastEventID="", epoch++, CloseIdleConnections, non-blocking signal on `switched chan struct{}`); every response-applying path captures the epoch before the request and discards results if `epoch` changed. `Register` installs the returned snapshot as `c.current` baseline (only if epoch unchanged). `Sync`: initial Snapshot failure → log and continue into the loop (start polling + stream); on `<-c.switched` → cancel stream, stop polling, reset backoff, immediate Snapshot + `startStream()`.
- `SuperHTTPRuntime` owns a `superSelector{urls []string; idx int; epoch uint64; consecutiveReportFailures int; lastSuccess time.Time; now func() time.Time}`. Qualifying successes (reset counter, set lastSuccess): Register 200, Report 2xx, Snapshot 200/304, SSE 200 connected. Report failures: `ErrControlUnknownPeer` → NOT counted (re-register path); any other error (transport, timeout, 4xx incl. 401, 5xx) → counter++. Single owner: `reportLoop` evaluates after each report attempt: rotate if `consecutiveReportFailures >= 3` OR `now-lastSuccess >= max(3×ReportInterval, 15s)` (only when `len(urls) > 1`). Rotation: `idx=(idx+1)%len`, `epoch=client.SwitchBase(urls[idx])`, then `requestReregistration(force=true)` (throttle keyed by epoch: one forced attempt per epoch; same-epoch unknown-peer attempts keep the 30s rule; a still-running older-epoch attempt's completion is ignored). `applySnapshot` ignores snapshots whose epoch ≠ current. No automatic fail-back.
- `bootstrapInitialBind` (main_edge.go): iterate `ResolveAPIUrls()` in order with per-attempt budget `max(2s, total/len)`; on success return ports AND the index; runtime starts with `idx` = that index.
- Generated edge profiles (`gencfg`, `ManageV2.buildEdgeConfigV2`): `APIUrls = [self APIUrl] + Cluster.Peers[].APIUrl` (in config order), `APIUrl` left empty when APIUrls has >1 entry (kept for single-super compatibility otherwise).
